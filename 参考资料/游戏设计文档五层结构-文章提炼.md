## 一、问题定义：为什么必须分层

AI 降低的是**游戏制作**难度，没有降低**游戏设计**难度。常见的三种烂尾形态：

1. 只有一个点子，就不知道怎么继续
2. 游戏做了一半越做越乱 —— 不知道开发进度，不知道下一步该干什么
3. 甚至要对整个底层进行重构

**根因**：没有对游戏设计层次进行划分 —— 不知道该怎么划分，也不知道划分之后该填充什么内容。

导致三个「不知道」：不知道游戏该有哪些设计做支撑 / 不知道下一步该完成什么 / 不知道该围绕什么内容进行设计。

## 二、五层文档结构（核心）

| 层 | 文档 | 负责什么 |
|---|---|---|
| ① | **GDD（游戏总体设计文档）** | 游戏定位、核心体验、核心玩法、核心循环、整体设计方向 |
| ② | **系统设计文档** | 各系统的功能、运行规则、交互流程、边界条件 |
| ③ | **内容设计文档** | 角色、武器、道具、敌人等具体内容 |
| ④ | **关卡设计文档** | 关卡结构、挑战配置、玩家引导、难度节奏 |
| ⑤ | **数值设计及配置文档** | 各项数值、成长速度、资源产出、玩法平衡 → 可执行的配置数据 |

### ① GDD —— 核心体验是第一优先级

> 其中最重要的属性是**核心体验**，之后几乎所有的设计都是为了围绕实现玩家核心体验来设计。核心体验设计很大程度决定游戏是否好玩。

### ② 系统设计文档 —— 固定内容清单

原文列出的 **12 项**：

系统定位 / 设计目标 / 系统框架 / 系统流程 / 系统入口与出口 / 核心对象 / 核心功能 / 核心规则 / 公式设计 / UI 交互设计 / 配置需求 / 资源需求

作者注：涉及内容较多，暂时不展开，后续另开一篇文章。

### ③ 内容设计文档 —— 玩家最能感受到，也最常被骂

- 负责设计角色、武器、道具、敌人等具体内容，丰富玩法选择，并确保内容符合游戏整体设计目标
- **作者认为最难的部分是：如何平衡不同玩家画像的需求**

### ④ 关卡设计文档

规划关卡结构、挑战配置、玩家引导及难度节奏；组织游戏内容，**引导玩家获得预期的核心体验**。

### ⑤ 数值设计及配置文档

制定和调整游戏中的各项数值，控制成长速度、资源产出及玩法平衡，并把设计结果**转化为可执行的配置数据**。

## 三、分层带来的四个能力

> 策划文档的目的不是把游戏写得多么复杂，而是帮助开发者**明确设计目标、理清规则关系**，并让游戏能够**持续开发和迭代**。

具体能更清楚地知道：

1. 游戏需要哪些设计内容
2. 各部分之间如何关联
3. 当前应该优先完成什么
4. 后续该如何推进

以及在开发过程中：检查设计遗漏 / 定位问题 / 根据测试反馈调整 —— **尽可能减少因设计混乱导致的重复开发和大规模返工**。
