## 1. 核心体验(已定)

通过三消发动技能,击败敌人并领取奖励,进而强化或改变技能的游戏。
核心体验 = 三消的简单易上手策略性 + 快速爽感,结合肉鸽的随机性和成长感。

## 2. 核心机制(已定)

- 三种颜色方块 = 1 角色的三个技能(每技能对应一种颜色)
- 消除数量多少定技能效果强度
- 玩家回合固定行动次数,单次交换消耗 1 点(无效交换回滚不消耗,连锁消除免费),归 0 切敌方回合,双方循环
- 肉鸽层 a+c:局内 build 随机 + 局内地图/事件随机
- 策略性主要在肉鸽玩法上体现

## 3. 范围(W2 规则定稿,数字待 W3)

> 规则部分已定稿。数字部分(各档伤害/护甲/增幅% / 减伤% / MP 数值等)走 JSON 配置,W3 填。

### 3.1 棋盘
- 10 列 × 4 行(可配)
- 横向重力:新方块**左侧补**,旧方块**往右掉**
- 3 色方块:棕(挥砍) / 白(护甲) / 黑(增幅)

### 3.2 回合与行动
- 一回合 6 行动(可配)
- 每次行动 = 1 次交换(4 方向:上/下/左/右)
- **无效交换不消耗行动**(必须形成消除,否则回滚)
- **连锁消除免费**(消除后补充的方块若自动消除,不消耗行动)

### 3.3 消除规则(7 种形式,统一按 N 块映射,无形状特殊效果)
- 3/4/5 个同色行/列 → 3/4/5 消效果
- 2x2 同色 → 4 块(按 4 消效果)
- L 型(3+2 同色,附加 2 个连接)→ 5 块(按 5 消效果)
- 2x3 / 3x2 → 6 块(按 6+ 块效果)
- 7+ 块复杂形状 → 6+ 块效果
- 6+ 块 = 5 块效果 × 系数(每多 1 块 +20%,系数可配)

### 3.4 技能机制

**棕色(挥砍)** → 攻击 + 攒 MP
- 3/4/5 块:伤害 + MP 都按档位提升
- 6+ 块 = 5 块效果 × 系数

**白色(护甲)** → 护甲 + 自身减伤
- 3 块:护甲
- 4 块:护甲 + 5% 减伤
- 5 块:护甲 + 10% 减伤
- 6+ 块 = 5 块效果 × 系数
- 减伤 buff **多次消除取最大值覆盖**

**黑色(增幅)** → 增幅 buff
- 3/4/5/6+ 块 → 增幅 I/II/III / 6+ 系数
- 增幅 I/II/III 影响**棕伤害 + 白护甲**
- **不影响**:减伤率、MP 获取
- 肉鸽构筑可加"强化 0%"等占位设计

### 3.5 增幅 buff 行为
- **FIFO 队列**:多次消除黑色叠加,使用时优先消耗先产生的
- **跨回合保留**:直到消耗
- **消耗时机**:使用**其他颜色**(棕/白)消除时消耗队首
- **消耗 5 MP**:消除黑色后若 MP ≥ 5,自动消耗,获得**第 2 个 buff**(同档位,按时间入队)
- 强化默认触发(MP ≥ 5 → 下次消除黑色时自动消耗 5 MP)

### 3.6 角色(魔剑士,基于魔力的职业)
- MP 上限 10(可配)
- 通过攻击(棕色)积攒魔力
- 魔力到一定值消耗以强化其他技能(通过黑色辐射)

### 3.7 可配字段清单(全部走 JSON,数字待 W3)
- **战斗循环**:棋盘行/列、行动次数
- **角色**:MP 上限、MP ≥ 5 阈值、护甲硬封顶(默认 99999)
- **棕 N 块**:伤害 X_N、MP Y_N(N = 3,4,5,6+)
- **白 N 块**:护甲 Z_N、减伤%(4 块 5%、5 块 10%)
- **黑 N 块**:增幅 I/II/III %(影响棕/白)、6+ 系数
- **6+ 块规则**:每多 1 块 +20% 系数(可配)
- **公式档位**:数值表(默认,档 1)

## 4. 详细系统设计(W4 机制清单 · 进行中)

### 4.0 核心算法

> 跨模块的算法规则。所有具体实现细节 W5+ 决定。

**消除检测** (A. 连通块 + 形状判断)
- BFS/DFS 找同色连通块,>= 3 块消除
- 7 种形式归类:3/4/5 横/竖 / 2x2 / L 型 / 2x3 / 3x2 / 7+ 复杂
- 统一按 N 块映射(消除 N 块 = 该 N 块对应的技能效果)

**交换验证**
- 交换 2 个相邻方块(4 方向)
- 交换后**必须形成消除**,否则**回滚**(不消耗行动)
- 优化:只检测交换涉及的 2 个方块所在的连通块(W5+ 性能优化)

**重力补充** (A. 整盘重排)
- 消除 → 整盘压紧(col 0 方向)→ 一次性补满
- 补满后再跑消除检测,直到不形成消除

**连锁检测**
- 整盘检测(每次补充后都跑)
- **新方块参与连锁**(下落后若形成则参与)
- **不消耗行动**

**技能结算** (B. 每次消除立即结算)
- 每次消除 → 立即结算(扣血/护甲/buff)
- 检测连锁 → 补充 → 触发消除 → 立即结算
- 直到不再形成消除 → 结束
- 理由:单次消除立刻结算让强度平衡好控制,支持复杂技能

**buff 触发顺序** (A. 按触发时机 + `priority` 字段)
- `priority: int`(默认 0,数字越小越先)
- 同 trigger 内按 priority 排
- 同 priority 按 buff_queue FIFO
- 不同 trigger 自然时序(`on_block_clear` → `on_hit` → `on_turn_start` → ...)

### 4.1 棋盘系统

> 基础规则定稿,具体数据结构 / 算法细节 W5+ 实现阶段决定。

**基础**
- 10 列 × 4 行(可配,40 位)
- 横向重力:新方块**左侧补**,旧方块**往右掉**
- 3 色方块:棕(挥砍) / 白(护甲) / 黑(增幅)
- **始终满**(消除后立即补充,无空位)
- **多回合共用**(跨回合不重置)

**初始化**
- **保证开局**:有初始方块算法,初始无 3 连(具体算法 W5+)
- 棋盘多回合共用

**新方块来源**
- **随机池**(后续可升级为袋子系统)
- **一次性补满**:消 1 补 1(直到棋盘满 40 位)
- **新方块参与连锁**:下落后若形成则参与
- **补充时机**:消除和连锁结算后

**防卡关机制**
- **每次补充后检测**:棋盘是否还有"可交换形成消除"的位置对
- **如果无**:清空棋盘,重新补充(整盘重置)
- 检测算法:遍历所有可能的相邻交换,看是否形成消除(W5+ 实现)

**流程**
- 交换 → 消除 → 连锁 → 补充 → 判定(消 / 防卡关)→ 结束

**边界 / 特殊**
- 固定 40 位(可配),**肉鸽可加扩大/缩小棋盘**
- 无限补充 → **无全消除**
- 无特殊方块

**数据结构**(W5+ 实现细节)
- 坐标系:`(col, row)`,**行号向下增加**
- Godot 4 推荐:**1D array + `Vector2i`**
- 索引公式:`index = row * col_count + col`

### 4.2 回合系统

> 玩家整回合 → 敌人整回合(标准回合制),事件驱动状态机支持未来加 buff / 敌人技能。

**基础**
- 玩家整回合 → 敌人整回合(标准回合制)
- 玩家**手动结束**自己回合
- 敌人回合后**自动切换**至玩家回合

**AP / 资源恢复**
- AP 每玩家回合开始**回满**(可配,默认 6)
- MP 是**魔剑士特有资源,不自动恢复**(只能通过攻击 / 技能积累)
- AP 受 buff / 敌人技能影响(肉鸽可加)

**buff 跨回合**
- 全部通过字段配置(`duration` / `carry_over` 等)
- 增幅 / 减伤 是**魔剑士特有 buff**,其他职业自行配置

**状态机**
- 事件驱动,支持未来加 buff / 技能
- 状态:`player_turn` / `player_settling` / `enemy_turn` / `enemy_settling` / `battle_end`
- **默认不引入中断机制**,但状态机要支持未来加

**战斗结束**
- 玩家 HP ≤ 0 → 失败
- 敌人 HP ≤ 0 → 胜利
- **同时发生** → 默认玩家胜利,HP 设为 1(防意外)
- 无主动撤退 / 平局

### 4.5 敌人 + AI

> 敌人 = Character + AI 行为 + 攻击模式(数据驱动 JSON 加载)。

**敌人基础**
- 跟玩家一样的 Character 结构(§ 4.3)
- **没有 AP**,一回合行动次数根据设计来(可配)
- MP / 资源 / buff 队列(可配,根据敌人设计)
- 全部字段走 JSON

**敌人技能结构**
- **AI 触发的攻击模式**(不需要消除方块)
- 复用 Effect 数据结构(§ 4.4):`list[Effect]`
- 触发模式:`trigger` 字段(periodic / charge / counter / on_turn_start / on_hp_threshold 等)
- 触发参数:`params` 字段
- 目标:`target` 字段(player / self 等)

**AI 行为**
- type 枚举(已定):random / charge / counter / periodic
- **初步采用 periodic 形式**
- 加上关键节点的特殊机制或技能(`on_hp_threshold` 等)
- AI 行为组合一般只有 1 个(简化)

**攻击模式**
- 复用 Effect + Buff 数据结构(§ 4.4):
  - **伤害** = `Effect(type="damage", params={value: N})`
  - **DoT** = `Effect(type="dot", params={damage_per_turn: N, duration: M})`
  - **debuff** = `Effect(type="buff", params={buff_type: "debuff_X", value: -V, duration: M})` 给玩家施加负向 buff
- 攻击效果组合:`list[Effect]`,支持多效果一次攻击

**拓展**
- **数据驱动**:全部从 JSON 加载
- 强度和难度通过**数值配置 + 机制设计**(可配)

### 4.6 肉鸽系统

> 节点图 + 局内 build 构筑(符文 / 装备 / 一次性道具),数据驱动 JSON 加载。

**局内地图**
- 节点图,每个节点后 **2 选 1** 进入下一节点
- 不需要路径/地图可视化,直接选择

**节点类型**(5 种)
- **战斗**:进入 → 战斗 → 奖励 → 下一节点
- **事件**:进入 → 描述+选择 → 触发 → 奖励 → 下一节点
- **商店**:进入 → 商店页面 → 点击购买(金币不足红色 / 足够白色)
- **休息**:恢复 HP 比例 → 下一节点
- **BOSS**:同战斗

**局内 build(3 件套)**

- **符文** = 颜色绑定技能(黑白棕 × 3 槽 = 9 槽)
  - **Rune 跟 Skill 1:1 关系**,复用 Skill 字段表 + `tags: list[FlowTag]` 字段
  - 职业有**固定符文池**,战斗/商店/事件抽取 N 个供选择
  - **加权算法**:基于 **3 个** bd 流派的标签,玩家当前持有标签最多的更容易抽到
  - 具体流派名 / 内容 W4 后定

- **装备** = 永久 buff
  - 复用 Buff + `slot: enum("head", "chest", "weapon", ...)` 字段
  - 效果偏通用

- **一次性道具** = 战斗中消耗
  - 复用 Effect + `max_count: int = 5` 字段
  - 使用时触发效果

**奖励 / 选择**
- 战斗 / 事件具体设计,后续

**难度 / 平衡**
- 跟**局内进度**挂钩(具体后续)
