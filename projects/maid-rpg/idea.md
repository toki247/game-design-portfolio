## 为什么重构成五层

原来这份文档是**一个 1267 行的混合文件** —— GDD、系统规则、模块数值、构筑验证、章节剧情全挤在一起。代价是:改一处要翻全文找上下文,「下一步该做什么」只能靠记忆,不同性质的设计混在同一标题下,review 时也看不出哪块是真的定了。

现在按 **GDD → 系统设计 → 内容设计 → 关卡设计 → 数值与配置** 五层组织。**每条设计内容只存在于一个文件里** —— 改规则去 02,改数值去 05,加内容去 03,排关卡去 04,改核心体验去 01。

> 分层依据:小黑盒《AI能帮你写代码,但游戏究竟该怎么设计?》(作者 陌情)提出的五层文档结构。原文要点:「策划文档的目的不是把游戏写得多么复杂,而是帮助开发者明确设计目标、理清规则关系,并让游戏能够持续开发和迭代。」

## 写东西的规矩

1. **先问是哪一层** —— 核心体验 → 01;规则 → 02;具体东西 → 03;流程 → 04;数字 → 05。
2. **改数值只动 05 + `config/*.tres`**,不动代码(已定 10)。
3. **改规则动 02**,如果影响具体模块,同步 03。
4. **新决议写进 02 §8**,标日期,不要只在正文里悄悄改。
5. **待定的东西不要删**,登记到 05 §4,填一个划一个。
6. **每层末尾都有「缺口清单 / 本层缺口」** —— 那就是「下一步该做什么」的答案。
