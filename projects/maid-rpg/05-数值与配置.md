# 05 · 数值设计及配置文档

> **职责**:制定和调整游戏中的各项数值,控制成长速度、资源产出及玩法平衡,并将设计结果转化为可执行的配置数据。
> **上游**:`02-系统设计.md`(规则 → 公式)、`03-内容设计.md`(具体模块 → 数值)
> **下游**:Godot `config/*.tres`(唯一落地点)
> **状态**:公式已定 ✅ / 全局占位值已有 🟡 / **大量数值待定** 🔴

---

## 0. 两条铁律

| # | 原则 | 落地方式 |
|---|---|---|
| 1 | **所有数值走配置** | 倍率 / 层数 / 阈值 / CD / 上限 / 公式常量全部走 Godot `Resource` `.tres`,逻辑代码不写死数字 |
| 2 | **规则是代码,数值是配置** | 「强击最多 5 回合」「双档切换」「结算六步顺序」这类**规则本身**写死在代码;**具体数值**走配置 |

> **为什么这条这么重要**:27 构筑 × 3 核心的数值量很大,硬编码后期维护成本极高。而且数值调试期改配置不用重编译,是战斗手感迭代速度的关键。

## 1. 公式速查

> 完整推导与选型论证在 `02-系统设计.md` §1.9,这里只放速查表。

### 1.1 属性派生

| 数值 | 公式 |
|---|---|
| HP | 体格 × 2 |
| 攻击力 | 力量 + 武器攻击 + buff |
| 防御 | 体格 |
| 行动条速度 | 行动速度 × 2(条 / 秒) |
| 闪避率 | (幸运 + 速度) / 2(向上取整) |
| 暴击率 | (技巧 + 幸运) / 2 |
| 暴击伤害 | × 1.5 |
| 命中率 | 技巧 − 对方闪避 |
| 冲击力 | 招式伤害 × 招式冲击力倍率 |
| 屏障最大值 | 防御 × 5 |

### 1.2 受击结算(六步,顺序不可换)

```
1. 判定闪避 / 招架        → 未命中直接返回 0
2. 扣防御穿透 → 有效防御 = max(0, 防御 − 穿透)
3. 减伤率 = 有效防御 / (有效防御 + K) → 最终承伤
4. 判定破防(韧性打空)     → × 1.5
5. 护盾优先吸收 → 溢出扣 HP
6. 累积韧性
```

### 1.3 行动条

| 项 | 值 |
|---|---|
| 满值 | 1000 |
| 跑条速度 | 行动速度 × 2(条 / 秒) |
| tick | 0.2 秒 |
| 并列 | 玩家先动 |
| 溢出 | 清零(不保留) |

### 1.4 逃跑

```
成功率 = 速度 / (速度 + K_escape)   ← 用 5 属性里的【速度】,不是行动速度
BOSS 战禁逃,无消耗
```

> ⚠️ **K_escape 与减伤的 K 是两个不同的常数**,建议在配置里分开命名 / 分组,别混。

## 2. 全局配置入口

建议 `config/combat_config.tres` 承载以下字段(初版占位):

| 字段 | 类型 | 占位值 | 说明 |
|---|---|---|---|
| `action_gauge_max` | int | 1000 | 行动条满值 |
| `action_gauge_speed_mult` | float | 2.0 | 行动条速度 = 行动速度 × 此值 |
| `tick_interval` | float | 0.2 | tick 间隔(秒) |
| `k_damage_reduction` | float | **100(待定)** | 减伤常数除法的 K |
| `k_escape` | float | **100(待定)** | 逃跑公式的 K |
| `tenacity_coefficient` | float | **待定** | 冲击力 → 韧性累积的换算比 |
| `broken_damage_mult` | float | 1.5 | 破防增伤倍率 |
| `shield_max_ratio` | float | 1.0 | 护盾上限 = 当前最大 HP × 此值 |
| `strong_mode_max_turns` | int | 5 | 强击模式回合上限(规则写死代码,此处仅供 UI 显示) |
| `strong_exit_hp_ratio` | float | 0.10 | 武士刀退出保留血量 = 身外身层数 × 此值 |

> **`strong_mode_max_turns` 特殊说明**:它既是规则又是 UI 需要显示的数字。规则在代码里写死(不可配),UI 读取配置里的同一份值 —— 两者必须一致,配置只作显示用途。

## 5. 数值调试基准

调平衡时用的参考坐标(已知):

| 场景 | 数值 | 说明 |
|---|---|---|
| 行动速度 100 | 约 5 秒一次行动 | 每秒涨 200 条,1000 条跑满 |
| 行动速度 50 | 约 10 秒一次行动 | 每秒涨 100 条 |
| 每 tick 增量(行动速度 100) | +40 条 | 100 × 2 × 0.2 |
| 一次战斗 20 回合 | 约 100 秒 | ⚠️ 基准假设,未验证 |
| 减伤率 | 防御 / (防御 + K) | K=100 时:防 50 → 33%,防 100 → 50%,防 200 → 67% |
| 防御穿透 | 减法扣有效防御 | 低防段收益更大(常数除法递减) |

**调试建议**:
- 任何一条曲线改动后,重跑一遍 `27 构筑验证` 的判定表,看有没有组合从 ⚠️ 变 ❌
- 改 `K` 会同时影响:减伤率、招架率(招架率 = 闪避率 + 减伤率)、武士刀构筑强度 —— 这三处要一起看
- 改韧性上限会同时影响:破防频率、双刀构筑、喷射装置的定位 —— 这三处要一起看
- **纯逻辑层不 extends Node**,才能脱离场景跑几千次循环做数值调试

## 6. 配置化落地要求

| 层 | 放什么 | 例 |
|---|---|---|
| `data/*.gd` | Resource 类定义,只有 `@export` 字段,**不放数值** | `combat_config.gd` / `skill_data.gd` / `module_data.gd` |
| `config/*.tres` | 实际数值实例,**改平衡只动这里** | `config/combat_config.tres` / `config/hands/*.tres` |
| `scripts/core/` | 规则逻辑,读配置不写死数字,不许 `extends Node` | `stats_calc.gd` / `damage_pipeline.gd` |

**必须走配置的**:倍率 / 层数 / 阈值 / CD / 上限 / 公式常量 / 能量槽容量 / 技能伤害倍率 / 冲击力倍率 / **行动速度(每个单位的基准值)**。
**必须写死在代码的**:5 回合上限 / 双档切换规则 / 结算六步顺序 / 溢出清零 / 三核心字段不共用。
